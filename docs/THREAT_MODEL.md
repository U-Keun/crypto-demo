# Threat Model

이 문서는 crypto-demo 프로젝트의 보안 위협 모델을 정의합니다.

## 프로젝트 범위

**목적**: 교체 가능한 벤더 암호화 모듈과 DB 컬럼 암호화 통합 데모

**MVP 제약사항**:
- 교육/데모 목적
- 프로덕션 배포 준비 상태 아님
- 하드코딩된 키 사용
- 단일 인스턴스 운영 가정

## 보호 대상 (Assets)

### 1. 데이터

**암호화 대상**:
- ✅ DB에 저장된 사용자 전화번호 (phone)
- ✅ 전송 중 평문 데이터 (HTTP body)

**암호화 미적용**:
- ❌ 사용자 이름 (name) - 평문 저장
- ❌ 메타데이터 (id, created_at) - 평문 저장
- ❌ 검색 토큰 (phone_token) - 단방향 HMAC

### 2. 암호화 키

**현재 보호 수준**:
- ⚠️ 소스 코드에 하드코딩 (`[0x42; 32]`)
- ⚠️ 메모리에 평문 저장
- ⚠️ 키 회전 미지원

**권장 보호 수준** (프로덕션):
- 환경 변수 주입
- KMS 통합 (AWS KMS, Vault 등)
- 메모리 보호 (mlock, secure heap)
- 정기적인 키 회전

### 3. Provider 바이너리

**무결성**:
- ⚠️ 서명/검증 미구현
- ⚠️ 바이너리 변조 감지 불가

**권장**:
- Code signing
- 체크섬 검증
- Secure boot

## 위협 시나리오

### 위협 #1: 데이터베이스 유출

**공격자**: DB 파일(`crypto_demo.db`) 획득

**보호 수준**: ✅ 부분 보호

**결과**:
- ✅ 전화번호는 암호화되어 있음 (키 없이 복호화 불가)
- ❌ 사용자 이름은 평문 노출
- ❌ 검색 토큰은 평문 (단, HMAC이므로 역산 불가)
- ❌ 메타데이터 (생성 시각 등) 노출

**완화책**:
- DB 파일 암호화 (OS 수준 또는 SQLCipher)
- 파일 시스템 접근 제어
- 감사 로그

### 위협 #2: 메모리 덤프

**공격자**: 서버 프로세스 메모리 덤프 획득

**보호 수준**: ❌ 미보호

**결과**:
- ❌ 암호화 키 평문 노출
- ❌ 복호화된 평문 데이터 노출
- ❌ Provider 핸들 내부 상태 노출

**완화책**:
- mlock으로 키 메모리 스왑 방지
- 메모리 scrubbing (사용 후 명시적 zero-out)
- Hardware Security Module (HSM) 사용

### 위협 #3: AAD 변조

**공격자**: 네트워크 MitM으로 AAD 수정 시도

**보호 수준**: ✅ 완전 보호

**결과**:
- ✅ 복호화 실패 (Tag 검증 실패)
- ✅ 컨텍스트 바인딩으로 재생 공격 방지

**예시**:
```
원본 AAD: table=users;field=phone;name=Alice
변조 AAD: table=users;field=phone;name=Bob
→ 복호화 실패 (422 Unprocessable Entity)
```

### 위협 #4: Ciphertext/Tag 변조

**공격자**: 암호문 또는 태그 수정

**보호 수준**: ✅ 완전 보호

**결과**:
- ✅ GCM 태그 검증으로 변조 감지
- ✅ 복호화 실패 (CRYPTO_ERR_CRYPTO)

**AEAD 특성**:
- Authenticity: 변조 감지
- Integrity: 무결성 보장

### 위협 #5: 재생 공격 (Replay Attack)

**공격자**: 이전에 캡처한 유효한 암호문 재전송

**보호 수준**: ⚠️ 부분 보호

**분석**:
- ✅ AAD로 컨텍스트 바인딩 (다른 컨텍스트에서 사용 불가)
- ❌ 시퀀스 번호 없음 (동일 컨텍스트 내 재생 가능)
- ❌ 타임스탬프 검증 없음

**완화책**:
- AAD에 타임스탬프 포함
- Nonce 재사용 방지 (DB에 nonce 기록)
- 세션 ID/요청 ID 포함

### 위협 #6: 부채널 공격 (Side-Channel)

**공격자**: 타이밍, 전력 소비, 캐시 패턴 분석

**보호 수준**: ❌ 미보호

**분석**:
- ❌ 타이밍 공격 대응 없음
- ❌ OpenSSL은 일부 부채널 공격에 취약할 수 있음
- ❌ 평문 길이 노출 (패딩 없음)

**완화책**:
- Constant-time 구현
- 패딩 추가 (길이 숨김)
- Hardware 암호화 (AES-NI)

### 위협 #7: 키 관리 취약점

**공격자**: 소스 코드 접근

**보호 수준**: ❌ 미보호

**결과**:
- ❌ 하드코딩된 키 노출 (`[0x42; 32]`)
- ❌ 모든 암호화 데이터 복호화 가능

**완화책** (프로덕션):
```rust
// 환경 변수
let key = env::var("CRYPTO_KEY")
    .expect("CRYPTO_KEY not set")
    .from_hex()?;

// KMS
let key = kms_client.decrypt("key-id").await?;
```

### 위협 #8: SQL 인젝션

**공격자**: 악의적인 입력으로 SQL 쿼리 조작

**보호 수준**: ✅ 완전 보호

**결과**:
- ✅ 파라미터화된 쿼리 사용 (`params![]`)
- ✅ rusqlite가 자동 이스케이핑

**예시** (안전):
```rust
conn.execute("SELECT * FROM users WHERE id = ?1", params![id])?;
```

### 위협 #9: DoS (서비스 거부)

**공격자**: 대량의 암복호화 요청

**보호 수준**: ❌ 미보호

**결과**:
- ❌ Rate limiting 없음
- ❌ 리소스 제한 없음
- ❌ 요청 크기 제한 없음

**완화책**:
- Rate limiting (tower-http)
- Payload 크기 제한
- Connection pooling
- 리소스 모니터링

### 위협 #10: 암호문 교환 (Ciphertext Swapping)

**공격자**: Alice의 전화번호 암호문을 Bob의 레코드에 삽입

**보호 수준**: ✅ 완전 보호 (AAD 사용 시)

**결과**:
- ✅ AAD에 `name=Alice` 포함되어 있어 Bob 컨텍스트에서 복호화 실패
- ✅ 컨텍스트 바인딩으로 필드 간 교환 방지

**주의**: AAD를 올바르게 구성해야 효과적

## 공격자 모델

### Threat Actor 분류

**1. External Attacker (외부 공격자)**
- 능력: 네트워크 트래픽 스니핑, MitM
- 목표: 전송 중 데이터 탈취
- 대응: HTTPS 사용 (MVP에서 미구현), AEAD

**2. Database Attacker (DB 접근 공격자)**
- 능력: DB 파일 읽기
- 목표: 저장된 개인정보 탈취
- 대응: 컬럼 암호화 (현재 구현됨)

**3. Memory Attacker (메모리 접근 공격자)**
- 능력: 프로세스 메모리 덤프
- 목표: 암호화 키 탈취
- 대응: ⚠️ 미구현 (mlock, HSM 권장)

**4. Malicious Insider (내부자)**
- 능력: 소스 코드, 서버 접근
- 목표: 시스템 전체 장악
- 대응: ❌ MVP 범위 외 (접근 제어, 감사 로그)

## 보안 기능 요약

| 위협                | 보호 수준 | 구현 상태      | 비고                        |
|---------------------|----------|---------------|----------------------------|
| DB 유출             | ✅ 부분   | 완료          | 전화번호만 암호화            |
| 메모리 덤프         | ❌ 없음   | 미구현        | mlock, HSM 필요             |
| AAD 변조            | ✅ 완전   | 완료          | AEAD 태그 검증              |
| Ciphertext 변조     | ✅ 완전   | 완료          | GCM 태그                    |
| 재생 공격           | ⚠️ 부분   | 부분 완료     | 타임스탬프 미포함           |
| 부채널 공격         | ❌ 없음   | 미구현        | Constant-time 필요          |
| 키 관리             | ❌ 없음   | 하드코딩      | KMS 통합 필요               |
| SQL 인젝션          | ✅ 완전   | 완료          | 파라미터화 쿼리             |
| DoS                 | ❌ 없음   | 미구현        | Rate limiting 필요          |
| 암호문 교환         | ✅ 완전   | 완료          | AAD 컨텍스트 바인딩         |

## 명시적 비보안 범위 (Out of Scope)

다음 항목들은 MVP 범위에서 **의도적으로 제외**되었습니다:

### 네트워크 보안
- ❌ HTTPS/TLS (HTTP만 지원)
- ❌ 인증 (Authentication)
- ❌ 권한 부여 (Authorization)
- ❌ Rate limiting
- ❌ CORS 정책

### 키 관리
- ❌ KMS 통합
- ❌ 키 회전
- ❌ 키 파생 (KDF)
- ❌ 다중 키 버전 관리 (keyver 컬럼만 존재)

### 감사 및 모니터링
- ❌ 감사 로그
- ❌ 침입 탐지
- ❌ 이상 탐지
- ❌ 알림 시스템

### 데이터 보호
- ❌ DB 파일 암호화
- ❌ 백업 암호화
- ❌ 로그 마스킹
- ❌ PII 삭제 정책

### 가용성
- ❌ 고가용성 (HA)
- ❌ 재해 복구 (DR)
- ❌ 백업/복원
- ❌ 부하 분산

## 프로덕션 체크리스트

프로덕션 배포 전 반드시 구현해야 할 항목:

### Critical (P0)
- [ ] 환경 변수로 키 주입 또는 KMS 통합
- [ ] HTTPS/TLS 활성화
- [ ] 인증/권한 부여 구현
- [ ] Rate limiting
- [ ] 입력 검증 강화

### High (P1)
- [ ] 감사 로그 (누가, 언제, 무엇을 암복호화했는지)
- [ ] 키 회전 메커니즘
- [ ] DB 백업 암호화
- [ ] Secrets 관리 (Vault, AWS Secrets Manager)
- [ ] 모니터링 및 알림

### Medium (P2)
- [ ] 메모리 보호 (mlock)
- [ ] 부채널 공격 대응
- [ ] 재생 공격 완화 (timestamp in AAD)
- [ ] 입력 크기 제한
- [ ] 에러 메시지 sanitization

### Nice-to-Have (P3)
- [ ] HSM 통합
- [ ] Field-level encryption for all PII
- [ ] Homomorphic encryption (검색 가능 암호화)
- [ ] Zero-knowledge proof
